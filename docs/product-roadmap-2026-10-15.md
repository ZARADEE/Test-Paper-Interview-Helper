# 组卷助手：融合现有优势的后续发展规划

日期：2026-10-15。性质：目标产品与实施计划，所有新能力均为待开发。

依据：[本轮竞品比较](github-competitor-comparison-2026-10-15.md)、[逐项验收表](competitor-acceptance-2026-10-15.csv)及其中引用的固定版本证据。以下目标数值是建议门槛，不是测量结果；工期是资源假设下的初估。

## 1. 产品方向与优先取舍

**定位：一张能把“资料、练习、实验、模考、复习和陪伴”真正连起来的考研书桌。**

目标不是用聊天替代所有页面，而是让用户在当前题目、资料或任务中获得帮助。四个一级入口继续保留：**首页 / 考研组卷 / 小题狂练 / 试卷模板**。新能力放在现有任务的上下文里，成熟且高频后才考虑新增一级入口。沿用硬边框、平面色块、实体阴影、中文短标签及已有桌宠。

阶段顺序：

1. 先打通有出处的资料、题目和作答；把可信度做进功能。
2. 再让每个错误产生具体补弱任务，并能证明已经掌握。
3. 补齐完整模考及四科实验，把多模块组合变成学习优势。
4. 扩展多媒体学习包、手写和口述、手机接续及桌宠成长。
5. 用固定竞品版本的相同任务验收；未覆盖项始终保留，直到最终满足超越条件。

### 1.1 已完成，作为回归底线

主观题输入/自评/改判、Agent 辅助评分、FSRS 四档与历史优化、八类过程图解、45 个 OS 实验、四套桌宠、番茄钟、待办、题卷/答案册成套导出、题库增量加载，均不再列为“新功能”。

尤其保留：Agent 默认关且显式调用；API Key 不写入学习数据库；答案展开前不泄露；本地无 Key 可以学习；既有用户修改不会被题包覆盖；知识地图和学习记录仪大面板不恢复。事实依据见比较文档 L01–L09。

### 1.2 三个最终演示必须真正做完

- **错题补弱**：错题 → 证据 → 错因 → 微课/实验 → 未见变式 → 延迟无提示复测 → 桌宠完成任务。
- **资料学习**：一章资料 → 审核学习包 → 三科任务安排 → 多端回忆 → 原资料修订后的影响提示。
- **整卷复盘**：蓝图 → 固定试卷 → 可恢复混合答卷 → 可复核批改 → 时间/错因复盘 → 三日补弱 → 一周换题复测。

## 2. 十个产品工作包

每包都写清：用户收益、竞品基线、已有可复用部分、增量设计及验收。工作包不是十个一级菜单。

### P01 · 资料证据中心：让答案回到材料

**对标**：DeepTutor、AnythingLLM、PageLM；相关验收 E01–E05。

**入口**：小题狂练 → 知识点阅读内部增加“资料”；题目解析中增加“查看依据”。

**完整能力**：

- 管理 PDF、DOCX、Markdown、TXT 与图片，记录文件摘要、页码/区域、学科和版本；公式解析不确定时保留原图。
- 本地全文检索先可用，再增加可选向量检索；按学科、年份、题库、资料范围筛选。
- 划选段落即可提问、做笔记、建卡片或关联题目；回答的引用可以回跳到原页/原段，而非只写文件名。
- 资料更新产生新版本；展示受影响的题、卡片和讲解。旧作答继续引用旧快照。
- 默认只用用户选择的资料；缺依据时明确回答缺什么；不因相似关键词拼接跨年政治答案。

**保留与扩展**：复用 `source_documents`、题面预览、导入审核、KaTeX 和独立题库；新增 `source_revisions`、`source_spans`、`artifact_citations`，而非替换原导入链路。

**拟定验收**：100 条三科人工标注检索问题，引用段命中率目标 ≥95%；所有生成引用 ID 均能解析到来源或清楚显示来源缺失；无材料问题进入待补充；20 个跨版本/同名文件用例不串引用。检索命中和最终回答正确率分开评测。

### P02 · 错因驱动补弱：让“再来一道”有理由

**对标**：Oppia、DeepTutor；E06–E10。

**入口**：题目提交后的解析区，展示“这次错在哪里 / 接下来做什么”；首页只展示可执行任务。

**完整能力**：

- 建立具体误区和先修关联，例如“页号与偏移混淆”，不能只有“粗心/不会”两类。用户可修正诊断。
- 三层帮助：概念提示 → 关键步骤 → 完整参考解；记录每层是否使用，不把辅助答对当独立掌握。
- 根据误区选已有可信题，必要时给经审核的变式。原题重复答对与未见题迁移分别记录。
- 5–10 分钟补弱卡串联资料、已有图解、实验、变式和一次解释题。先修只在需要时出现。
- 复测接入既有 FSRS；保留人工四档，不能将 AI 判断直接变成 Good。

**数据**：`skill_links`、`misconceptions`、`remediation_runs`、`help_events`，都关联稳定题 ID 和 revision。先从人工编排的 12 条链路做准，再扩展，不一口气自动生成整张知识图。

**拟定验收**：12 条跨三科链路全部可走通；每条至少一个反例和三道不同条件的题；所有有帮助的作答可识别；一次答错不会永久降低掌握状态；新增和既有 FSRS 不产生重复卡。

### P03 · 时间预算下的今日训练：计划能完成

**对标**：DeepTutor Task Board/Mastery、PageLM Planner、Habitica；E11–E13。

**入口**：首页现有待办与番茄钟；桌宠仍显示今日剩余。

**完整能力**：用户填考试目标、今日可用时间、科目偏好和休息日；系统用待复习、错因补弱、未覆盖章节和模考复盘组成计划。显示推荐原因、预计耗时与替换项。

规则模式先落地：到期负担和必须完成项优先，其余按用户权重安排；库存不足、时间不足时明确缩减/顺延。AI 可解释计划或提建议，不能偷偷改日历、复习评级或完成状态。用户手动锁定任务不被重排覆盖。

**拟定验收**：50 组固定输入，计划总时长不超过预算；实际超时可重新安排剩余；休息日、跨日、暂停卡、零库存均有结果；重复刷新不重复建任务。

### P04 · 完整模考与复盘：试卷、答卷和计时属于同一场考试

**对标**：Moodle、PageLM ExamLab、LearnHouse；E14–E18。

**入口**：考研组卷 → “开始模考”；模板继续管理题型、总分和时长。

**完整能力**：

- 区分训练模板和经可靠原卷/当年资料核验的年度蓝图，保存 `blueprint_version`，不擅自将当前可编辑模板称官方结构。
- 固定题目、分值、顺序和资源快照，建立混合题型答卷；支持答题卡、标记、分区、草稿及中断恢复。
- 训练模式允许暂停/超时；严格模考模式到点按配置提交。现有日常番茄钟与训练超时行为保持，不被新模式覆盖。
- 客观题自动判分，主观题沿用人工确认；总分可暂标“待复核”，不填假分凑总分。
- 复盘区分内容缺口与时间分配；可直接进入错因训练、实验和复习，不强制打开统计大屏。

**数据与实现**：在 `paper_package.py` 快照基础上加 `exam_sessions`、`exam_answers`、`exam_events`；计时基于截止时间，答案保存与交卷幂等，旧卷改题不改旧成绩。

**拟定验收**：30 个故障/恢复场景全部通过；混合题卷各科不少于一套；停止进程、重复交卷、到点断网/关闭窗口、时钟变更有明确结果；答案册与最终答卷逐题同版；严格模式无法通过普通取题接口取参考解。

### P05 · 四科实验与代码：把画面变成可验证的理解

**对标**：Algorithm Visualizer、OpenMAIC、LearnHouse；E19–E23。

**入口**：把现有“408 实验台”内容扩展为四科分组，保留已有 45 个 OS 实验及代码草稿。

首批新增建议 **18 个实验**，这是我们的发布范围，不是整个 Algorithm Visualizer 的覆盖率：

| 学科 | 首批内容 | 与题目联动 |
|---|---|---|
| 数据结构，6 个 | 排序对比、堆操作、BST/AVL、图遍历、最短路、最小生成树 | 从题干载入序列或图；先预测结果，再运行 |
| 组成原理，6 个 | Cache 映射/替换、流水线冒险、补码运算、浮点表示、寻址、微操作 | 位宽、时序和初态显式保存；计算与图示相互核对 |
| 网络，6 个 | CRC、滑动窗口、TCP 拥塞、子网划分、路由表、交换/转发 | 导入协议参数；比较参数变化导致的结果 |

新增统一 `ExperimentSpec`：输入、确定性状态、代码 trace、答案校验、引用和版本。每个实验有预测题、边界案例和关联练习。已有教学解释器继续可用；真实 C/C++/Python/Java 运行作为可选运行适配器独立交付，说明依赖、时限和支持范围。

**拟定验收**：首批每个实验至少 5 个已核验样例及 3 个边界案例；相同输入的计算、显示与题解一致；改变输入立刻标记旧结果；任意代码超时可停止；隐藏测试与参考实现不提前发送到学生端。

**全量扩展登记**：Algorithm Visualizer 的算法/tracer 目录以及 LearnHouse 宣称的 30+ 语言尚未完成全量冻结；列入最后阶段对标调查与适配。达成首批 18 个实验不得宣布全算法或全语言超越。

### P06 · 资料转学习包与微课：生成结果要进入训练

**对标**：PageLM、DeepTutor Book、OpenMAIC、LearnHouse；E24–E28。

**入口**：资料中心“生成学习包”，错题“补一个微课”。

完整学习包可含：可编辑章节/块、Cornell 笔记、题目、闪卡、图解、互动参数、测验、语音和字幕；先预览大纲再生成，支持暂停/恢复、单块重做与局部编辑。资料生成题必须入审核队列，原题、改编和生成题分别标记。

课堂补齐问答、白板、讨论和项目练习；多角色是按需教学工具，默认一个教师即可。所有角色共用证据约束，不以“多 Agent 同意”当正确性。

导出兼顾现有 PDF/DOCX，新增 Markdown、HTML 学习包及可编辑课件；音视频输出带字幕与来源。离线包显式检测外部资源，下载失败不能悄悄发布成“完整离线”。

**拟定验收**：10 个完整学习包覆盖三科；笔记、卡片、题目、音频可回到来源；源资料修改产生影响提示；重复导入无重复卡；取消生成不丢已编辑块；导出后断网演练全部必要资源。

### P07 · 手写、口述与步骤反馈：评价学生真正写了什么

**对标**：OpenMAIC 多模态教学、PageLM 语音转写，放大现有 `grading.py`；E29–E32。

**入口**：主观题作答区增加图片/手写附件、口述转写；政治材料题与数学多小问先试点。

图片先保留原件，转写结果并排校正，学生确认后参与评分；公式不可靠则待复核。给分关联评分点、具体步骤和原文/图上区域，允许等价解法。没有可信 rubric 就只给定性建议。

口述支持录音、文本校正、追问、再次作答与记录比较，可用于政治答题和知识点讲述。面试训练作为后续扩展模式，不把已有 Markdown 面试题库文件误称成已实现的模拟面试。

**拟定验收**：建立三科共 90 份人工标注作答，含等价解、步骤缺失、错推理、缺图和诱导文本；两位评阅者分歧先裁定。数值评分目标按题归一化 MAE ≤0.08，严重误判率目标 ≤2%；报告拒评/待复核占比和有效覆盖率，禁止通过全部拒评获得低误差。模型、prompt 与资料版本冻结，未过门槛仅保留建议功能。

### P08 · 桌宠任务成长：保留个性，并服务学习

**对标**：Habitica、DeepTutor Partners、PageLM Companion；E33–E35。

**入口**：现有桌宠与今日待办，不另外创建游戏首页。

用“独立完成复习、纠正误区、解决实验挑战、完成模考复盘”等事件解锁角色互动或纪念物；四个既有角色继续可选。每日可设低负担目标，允许休息日和关闭成长。

陪伴记忆只保存用户可查看和删除的偏好及学习事实，不给用户贴人格标签；AI 对话默认不开启。桌宠可展示下一任务和一句可核验反馈，点击直接进入上下文。

**拟定验收**：同事件重复回放/导入/同步仍只结算一次；单纯延长计时不增加学习奖励；断签不扣知识掌握或已有收藏；150% 缩放、多屏、计时窗和待办窗回归通过。

### P09 · 安装、恢复与随身复习：学习记录能带走

**对标**：Kolibri、AnythingLLM 的部署体验、学习平台的数据持久化；E36–E40。

先交付 Windows 可安装版本、应用内备份/恢复，再做移动端 PWA 和局域网/自托管同步。备份清单覆盖 SQLite、题目/资料资源、用户导入、笔记、复习历史、待办、实验草稿、桌宠及计时设置；当前数据横跨后端、localStorage 和 Electron userData，不能只打包一个 sqlite 文件。

手机第一阶段支持到期复习、知识卡、错题查看和口述，使用预缓存的题目与必要资源；离线创建事件，重连后确认同步。完整学习包导入等 R6 的 E28 完成后接入，不作为 R5 的前置依赖。桌面负责复杂组卷、实验和编辑。一个设备暂停的卡不会被另一设备旧状态偷偷恢复。

**拟定验收**：干净 Windows 环境首次安装、离线练习和升级保留数据；20 组全量备份/恢复与 30 组双端并发/断网场景；按事件 ID 幂等合并，删除有 tombstone，冲突可见；不使用“最后写入覆盖”无声丢历史。

### P10 · AI 服务与内容质量：全流程共用的基础能力

**对标**：AnythingLLM 模型/工作区、DeepTutor 版本化资料与能力管理；E41–E44。

- 保留显式调用；增加“本机模型”专用配置与健康检查，只允许明确配置的 loopback 服务，不能为支持 Ollama 而取消所有远程 SSRF 限制。
- 每项任务显示预计调用/实际用量、取消和预算上限；价格表由用户设置并标日期，没有价格时只展示 token 等实际用量，不能编造费用。
- 题目质量工作流：来源、审核、参考解争议、勘误、题目 revision、受影响产物及回滚；题包更新与用户改题冲突可见。
- 统一任务与事件接口，把资料、作答、图解、实验、复习、计划、桌宠和导出连接起来；异步任务可恢复。

**拟定验收**：无 Key 的核心功能全可用；取消不写半截成绩；错误响应不露凭据；源资料无证据、模型不可用、预算不足各有可继续的手动路径；题目更新不重写历史成绩。

## 3. 技术落地：扩展现有项目

### 3.1 数据对象与边界

| 新对象 | 关联现有对象 | 关键规则 |
|---|---|---|
| SourceRevision / SourceSpan | source_documents、预览区域 | 不可变版本；可追溯页/区域 |
| LearningArtifact | 题目、笔记、知识卡、实验规格 | 每个产物有来源与生成/审核状态 |
| RemediationRun | choice/subjective attempts | 记录错因、帮助、变式、复测，不能覆盖原作答 |
| StudyTask / TaskEvent | 首页待办、timer、review | 一个稳定 task_id，同事件只完成/奖励一次 |
| ExamSession / ExamAnswer | paper snapshot、timer | 答卷与试卷分离，交卷原子且幂等 |
| ExperimentAttempt | 现有 deterministic engines | 输入/模型版本/预测/结果/代码分开存 |
| SyncEvent / Tombstone | review events、笔记、任务 | 追加事件、revision 检查、冲突保留 |

关系链：`SourceRevision → QuestionRevision / LearningArtifact → Attempt → Diagnosis → RemediationRun → ReviewEvent`；`StudyTask` 引用这些对象，`PetRewardEvent` 只消费已提交的有效事件。

### 3.2 模块映射

| 现有文件/目录 | 计划怎么扩展 |
|---|---|
| `backend/app/extractors.py`、`document_preview.py`、`main.py` 导入流程 | 保留审核，补资料版本/区域索引；大任务新增独立 router |
| `backend/app/subjective.py`、`grading.py` | 逐小问、附件、可校正转写、评分证据与评测记录 |
| `backend/app/review_scheduler.py` | 继续使用现有 FSRS；新增任务引用，不复制第二个调度器 |
| `backend/app/paper_package.py`、`template_rules.py` | 快照上加答卷与蓝图，导出共用版本 |
| `frontend/src/components/PracticeWorkspace.tsx` | 在原练习/阅读/实验内部增加上下文入口 |
| `frontend/src/components/os-lab/`、`visuals/` | 共用实验规格和事件，逐步补四科 |
| `HomeDashboard.tsx`、`PetTodoPanel.tsx`、`ReviewTask.tsx` | 共用任务 ID 和状态，避免三处各算一遍 |
| `frontend/electron/timer-service.ts`、`main.ts` | 明确考试计时与日常计时，补安装/备份入口 |

不引入第二套登录、任务库或向量数据库作为第一步。先验证本地全文检索和真实资料，再根据索引规模决定可选向量适配器。新增事件日志是跨模块可靠性需要，不做全项目事件溯源重写。

### 3.3 体验规则

一个任务页只保留一个主要行动；补弱建议优先出现在刚做错的题旁边。深度证据、评分细节和技术配置按需展开。任何学习计划都可跳过或改写；进度视图只展示下一步，不恢复已移除的大面板。

## 4. 分阶段发布与依赖

**资源假设**：2 名全职工程师（前端/桌面、后端/AI），1 名内容/教研人员，兼职设计与 QA。没有这组资源就不采用下列日期承诺。以下是 **24–32 周工程窗口的初估**，周数从实际启动算起，不是已承诺发布日期。单人推进应按实际吞吐重排。

| 阶段 | 初估窗口 | 工作包 | 可交付成果及放行门槛 |
|---|---|---|---|
| R0 · 证据与基线 | 第 1–2 周 | P10 基础、P09 备份先行 | 冻结对标任务与样题；全量备份/恢复原型；保住所有旧回归 |
| R1 · 资料可查 | 第 3–6 周 | P01、P10 | 本地检索、页/区域引用、版本与资料问答；无 AI 可用 |
| R2 · 错因能修 | 第 7–10 周 | P02、P03 | 12 条补弱链路、预算任务、FSRS 联动；错题场景端到端 |
| R3 · 整卷能考 | 第 11–14 周 | P04、P07 文本步骤部分 | 可恢复混合答卷、严格/训练模式、复盘；已有纸质导出一致 |
| R4 · 实验能迁移 | 第 15–20 周 | P05、P06 首批微课 | 18 个新增实验、题参载入、预测挑战、10 个学习包 |
| R5 · 学习能接续 | 第 21–26 周 | P07 多模态、P08、P09 | 手写/口述试点、桌宠成长、安装包、手机复习与同步 |
| R6 · 完整对标 | 第 27–32 周，按差距调整 | P06 完整教学与全部包收尾 | 补齐 CSV 缺项；竞品并排体验与盲评；未达门槛继续开发 |

阶段可重叠的是内容标注、实验模型和界面；强依赖不能跳：**P01 → P02/P06；P10 事件 → P03/P08/P09；可靠备份 → 模型迁移；P04 快照 → 多端答卷；质量标定 → 自动评分放行。**

上述窗口覆盖本规划中冻结的考研学习流程，不等于在 32 周内复刻十个大项目所有功能。若现场发现重要新能力、内容不足或多端冲突复杂，按证据延长，不删除难项来维持完成率。

### 4.1 全产品最终目标的未覆盖登记

“完全超越”作为最终目标保留。以下属于需要继续研究与决定实现/集成方式的差距，不因排期靠后就视作已完成：

| 长期差距 | 对应标杆 | 后续动作 | 当前结论 |
|---|---|---|---|
| 全算法目录、各语言 tracer、完整语言评测 | Algorithm Visualizer / LearnHouse | 冻结子仓库、运行时矩阵、逐项测试与适配 | 未全量研究，未覆盖 |
| 全教学创作、可编辑多格式课件、协作白板/PBL | OpenMAIC / LearnHouse | 补教学创作与协作任务清单；区分个人与多人模式 | 本轮规划核心链路，全量待补 |
| 通用插件、外部工具、伙伴渠道与跨工作区能力 | DeepTutor / AnythingLLM | 先完成学习工具白名单；再逐能力冻结和复测 | 不能宣称通用 Agent 平台超越 |
| 全校级题型、课程管理、角色权限、第三方插件 | Moodle / Kolibri | 若转向机构版，单独产品线和数据隔离，不塞入个人首页 | 当前不实施，不计完成 |
| Enterprise 支付/SSO/多组织 | LearnHouse | 商业模式明确后单独立项 | 当前不实施，不计完成 |
| 多人公会、社交与完整 RPG 经济 | Habitica | 先验证个人成长是否提升真实学习，再决策社交线 | 当前不实施，不计完成 |

只有所有纳入最终产品范围的差距完成、未知项已核清，并通过同等条件比较，才可以使用“整体功能超越”。在此之前逐模块报告实际进度。

## 5. 验收方法：100% 对齐，优势另算

### 5.1 功能覆盖

配套 CSV 记录 E01–E44。完整通过才算完成；“已有但未连通”“部分实现”“待开发”均不等于通过。分母冻结后新增需求另列变更记录，不用额外特色抵扣缺项。旧有功能单独回归，避免为了新功能牺牲现有体验。

本轮没有运行完整竞品并冻结所有交互细节，CSV 是可执行验收草案，**不是全产品功能普查已完成的证明**。R0 必须通过官方文档、源码与可运行流程补全清单，对不确定能力做实际核验。

### 5.2 同条件比较

| 指标 | 测法 | 放行原则 |
|---|---|---|
| 学习任务成功率 | 三个目标场景，同题、同资料，至少 10 名目标用户交叉试用 | 关键流程不弱于基准；失败原因逐条解决 |
| 完成成本 | 记录操作次数、耗时、求助次数与实际模型用量 | 初始目标：主要场景中位耗时比选定基准降低 ≥20%；先测基线 |
| 答案与引用质量 | 人工标注集，匿名评价引用/步骤/拒评 | 按 P01/P07 门槛，报告覆盖率与不确定区间 |
| 迁移与延迟记忆 | 未见变式、7 天及 30 天复测；记录是否看过提示 | 首轮探索性试验，样本不足不宣称显著提分 |
| 可靠性 | 重启、离线、并发、恢复、重复提交及升级 | 记录丢失、错卷评分、答案泄露、隐式付费为阻断项 |
| 模型公平性 | 同模型/版本/上下文/温度/预算；模型不可同配则分组报告 | 不能把更贵模型收益写成产品架构优势 |

### 5.3 内容工作量独立排期

工程能运行不等于题目和解析正确。内容人员需交付：12 条错因教学链、18 个实验金标准、10 个学习包、90 份评分样本、100 条引用问题、各科混合模考样卷及年度蓝图证据。政治按命题年份和资料版本组织；没有当年可靠依据的模板只称训练模板。

## 6. 第一批开发任务

先做一个真实可用的纵向流程，避免基础建设长期没有用户产出。

| 顺序 | 任务 | 交付与完成标准 |
|---|---|---|
| 1 | 冻结原功能回归与研究清单 | E01–E44 逐项对照；原有测试/截图记录建索引；未确认项有负责人 |
| 2 | 全量个人数据备份/恢复最小版本 | 三类存储全部进入清单；从备份恢复一套隔离用户数据 |
| 3 | 资料版本与来源区域 | 导入一份现有 408 资料；页/区域可定位，原图可用 |
| 4 | 本地全文检索与引用展示 | 不开 AI 也能查资料并回跳；已有题号可关联材料 |
| 5 | 一条页号/偏移补弱流程 | 错题→提示→已有地址转换实验→变式→复习，完整可用 |
| 6 | 统一任务完成事件 | 首页、桌宠和练习共用同一 task_id；重复操作只完成一次 |
| 7 | 固定样例验证与用户试用 | 原功能回归、真实材料准确性、5 人先导试用；修复后再扩 12 条链 |

首批暂不把云账号、社交、全站搜索或角色商城作为前置依赖。最早可以看到的新增价值应该是“做错后知道怎么补，并能检验是否真的补会”。

## 7. 主要风险及应对

| 实际风险 | 设计处理 | 验证点 |
|---|---|---|
| 高人气竞品迭代快，追的是旧版本 | 固定当前基准；每个发布阶段再记录变化，不改写历史结果 | 新增能力进差距登记，不假装原已覆盖 |
| 同一份错题在多个模块重复调度 | 单一题 revision、TaskEvent 和 ReviewEvent | 重试/恢复/同步不重复 |
| 生成笔记、题目或评分不可靠 | 来源、审核、金标准、人工确认、待复核 | 不用模型自评证明模型正确 |
| 资料与题包越来越大 | 分学科可选包、资源哈希复用、增量下载与按需解析 | 固定设备实测启动/检索/包体，不编造性能 |
| AI 服务成本失控 | 显式启动、预算、可取消、缓存可见、实际用量 | 失败重试也计费可见；无价格不报假金额 |
| 移动同步或升级丢数据 | 先全量恢复、再增量同步；旧版只读恢复路径 | 故障注入与真实备份回读 |
| 内容审核成为瓶颈 | 小范围人工做准，分学科批次扩展 | 内容门槛独立于代码完成率 |
| 功能堆积破坏原书桌体验 | 保留四入口、上下文展开、真实用户任务测试 | 新用户找题/做题步骤不增加 |

每次阶段评审只回答三件事：对齐项实际通过多少、三个学习场景还断在哪、已有优势是否退化。发布材料按事实写，不提前把规划当成绩。
