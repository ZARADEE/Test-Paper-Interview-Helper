# 组卷助手：GitHub 竞品调研与产品进化路线

> 2026-10-15 更新：本文为历史研究，后续选型请看[新一轮竞品功能对比](github-competitor-comparison-2026-10-15.md)和[发展规划](product-roadmap-2026-10-15.md)。本文提到的主观题、FSRS、图解等缺口已有后续实现，不应直接照旧立项。

> 别把书桌改造成驾驶舱。真正好的学习工具，应该让人少点两下，多想一步。

调研日期：2026-10-10（北京时间）\
对象：Test-Paper-Interview-Helper；面向考研数学一、政治、408 的本地学习工作台。\
交付性质：产品与工程调研、功能建议及验收方案；不是已实现功能清单。

## 1. 先说判断：我们应该在哪个方向做到顶尖

建议定位为：**面向考研自学者，把可信题库、主观题训练、整卷模拟、间隔复习和桌面陪伴串起来的本地学习工作台。**

现有产品已经把三个学科、组卷、导入审核、错题与桌宠放到同一个地方。下一阶段最有价值的工作，是让一道题从“被收进题库”真正走到“独立做对，并在一周后仍然会做”。

最重要的五个结论：

1. **主观题闭环应当先于继续堆题。** 当前 408 已有综合解答题与简答题，但在线练习的目录和会话仍以选择题为中心。能导出大题，不等于能练大题。[L1][L2]
2. **题库可信度需要成为产品功能。** 来源、原卷/改编、答案审核状态、勘误和修订历史，应该在题卡上看得见；数量只能说明规模，不能说明正确率。
3. **错题本需要升级为到期复习队列。** 借鉴 Anki / FSRS 的调度思想，把做错后的下一次练习安排好；不必恢复用户已经要求移除的知识地图、学习记录仪大面板。[S8][S9]
4. **AI 最值得先做的是分层提示与依据明确的批改辅助。** 当前 Agent 是从已有题中选题。保留它，但不要把所有智能化都押在组卷按钮上。[L3]
5. **下载即用、数据可恢复，是发布给陌生用户的基础。** 我们当前提供源码启动流程，frontend/package.json 未配置安装包构建脚本；与已有二进制发布的工具相比，首次使用门槛仍明显。[L4][S4]

建议的优先顺序：**可靠运行与数据保护 → 题目质量与试卷蓝图 → 主观题训练 → 到期复习 → 可追溯 AI → 交互讲解 → 手机伴随端。**

“顶尖”在本报告中有可检验的含义：新用户能顺利开始、答案有出处、训练覆盖主要题型、记录不丢、复习安排有效。当前没有用户研究、长期留存或学习增益实验，不能据此宣称市场第一。

## 2. 方法、证据等级与边界

### 2.1 调研范围

覆盖 12 个 GitHub 仓库：6 个直接/接近直接的备考产品，3 个相邻场景产品，3 个能力标杆。重点阅读 README、许可证信息、代码树，并抽查批改、可视化、备份、引用与纠错测试实现；同时对照本仓库相关源码。

- **D：官方文档声明。** README 或项目自己维护的文档；不代表独立实测。
- **C：代码抽查支持。** 已阅读具体实现；不代表整条用户流程已跑通。
- **L：本项目代码/文档事实。** 引用本地文件；代码结论与 README 口径分开。
- **P：产品建议。** 本报告提出的方案、工期和目标，均不是当前已有能力或实测指标。

本次没有逐一安装所有竞品，没有付费调用其模型，也没有复核竞品的每一道题。没有查到某项能力时写“未确认”，不直接写成“不支持”。星标、推送日期只是观察时点的元数据，不作为题目质量、真实活跃用户或学习效果的代理。

### 2.2 可复查材料

仓库元数据保存于 [GitHub 调研快照](research/github-competitor-snapshot-2026-10-10.json)，包含 canonical 仓库名、Stars、Forks、默认分支、推送时间、许可证 API 返回值、采集时间与可取得的版本标识。智镜的 commit 查询遇到 GitHub API 限流，未填伪造版本；保留已取得的树标识，引用采用分支链接。其余项目的具体固定版本入口见文末附录。

原链接 Tenzen-a10/zhijing408-offline 当前转向 TenLongLiu/zhijing408-offline；Super Productivity 原 johannesjo 地址转向 super-productivity 组织。后文使用 canonical 地址。[S2][S12]

用户已确认相关资料使用授权。本报告不重复要求授权；但公开发布时仍应把已取得的授权范围、内容许可与代码许可分别记录下来，避免后来贡献者误认为“GitHub 上能看到”就等于“所有素材统一开源”。

## 4. 逐个看：哪些功能值得学，怎样学

### 4.1 408Lab：让解析从一段文字变成可操作的讲解

**观察（D/C）**：README 声明 1,636 道题，由历年卷、精选题和十套模拟卷组成；选择题提供分选项解释。代码中的 visual-player.tsx 确实按类型分派排序、树、图、页面置换等过程组件。题库数字是项目声明，本次未重新计数。[S1][C1]

**值得借鉴**：

- 答错 B 时先展示 B 的误区，再解释正确项，而不是让用户在长解析里找答案。
- 页面置换、排序、网络窗口等题能逐步前进、回退，观察状态变化。
- 原卷、模拟卷、专项题明确分开，避免随机题拼接后被误认为原卷。

**落地到我们**：先选页面置换与排序两类高频、易验证过程题。复用已保留的数据描述，另建有类型的 visual spec 与小型 React 播放器；每一步必须能与答案对照。无描述的数据保留普通解析。选项解释逐题补录，不能把一个总解析复制成四份充数。

**边界**：README 标注部分含图真题做过文本化改编，因此“真题年份相同”不代表原题图文逐字保真。我们应在题卡显示“原卷整理/文字改编/原创模拟”，同时保留原来源。

**不照搬**：整套终端视觉、全量经验笔记面板、未验证的每题动画。先把一个过程讲清楚，再扩类型。

### 4.2 智镜408：借鉴学习路径，尊重现有界面取舍

**观察（D）**：单 HTML 离线使用，文档明确所谓 AI 组卷主要是规则选题；本地讨论不等于跨设备社区；浏览器数据清除可能导致记录丢失。[S2]

**值得借鉴**：错题 → 选择错因 → 查看相关解释 → 练同一薄弱点，形成可执行下一步。

**落地到我们**：把这一流程嵌入当前题目解析区。例如“页号与偏移混淆”之后提供 3 道同考点不同表述的题，再安排隔日回访。错因允许用户改写，算法只做建议。

**边界与取舍**：不重新引入用户已删去的知识地图和学习记录仪入口，不创建假多人讨论，也不把规则组卷改个名字当大模型。智镜并未提供通用开源许可，采用功能思想与已有授权内容时保留来源说明。

### 4.3 墨·题库：数学题最先要做到“看得清、找得到”

**观察（D）**：静态站按数学类别和年份组织试卷，自带 KaTeX 与字体、支持快捷键；自动评分只覆盖选择题，练习分不是考研卷面分；作答状态在刷新/切卷后不保留。[S3]

**值得借鉴**：年份与卷别导航、题干/答案/解析明确分层、公式排版、可达的键盘焦点。

**落地到我们**：逐步把数学题从图片预览升级为结构化 Markdown/LaTeX 与原图双视图。原图承担保真，文本承担搜索、复制、读屏与局部引用。先做人工核验过的样板卷，不一次 OCR 替换全库。

**边界**：数学填空的等价表达与大题步骤不能沿用选择题字符串比较；“选择题做对率”必须独立显示，不能当整卷得分。

### 4.4 Exameow：最值得拆开看的通用练习产品

**观察（D/C）**：提供多格式资料出题、表格题库导入、章节练习和多种题型。judge.rs 的结果为 correct 布尔值与 feedback；practice.ts 存在 selfCheck 人工判定逻辑。它不是已经验证的考研逐步采分引擎。[S4][C2][C3]

**值得借鉴**：简答题有明确输入、提交、反馈和人工改判路径；CSV/XLSX 导入先映射列名；生成与练习分开。

**落地到我们**：先实现无需 API 的“作答 → 展开参考解 → 按评分点自评 → 保存”，再接 AI 建议。导入先预览 20 行、提示缺答案/错题型/重复项，再提交审核队列。

**边界**：本地存储不意味着外部模型调用离线，发送材料给云模型仍需网络。README 的跨平台支持与安装包需要各系统实测后才能对用户承诺。

**不照搬**：暂不引入教师在线考试中继、实时屏幕答案悬浮窗；这些会拉长产品链路，也不能优先解决当前考研练习缺口。

### 4.5 OpenExam：从“源码能跑”走向“普通人会用”

**观察（D/C）**：与我们同属 Electron、React、SQLite 本地学习方向；文档涵盖 AI 辅导、题库导入、错题与成长。dataBackup.js 提供保存/打开备份文件的系统对话框；这只能证明入口存在，不能证明所有附件、迁移和恢复场景都可靠。[S5][C4]

**值得借鉴**：用户目录存数据，代码与题库种子分离，导入/备份入口明确。

**落地到我们**：提供“备份学习工作台”，包含 SQLite 一致性快照、待办与草稿、用户修改、附件索引及版本。恢复前自动备份现状，展示将恢复的题量、记录数、缺失附件；提供回滚。

**不照搬**：立即建立全套经验值、徽章、等级系统。我们的桌宠已有个性，先让陪伴服务今日任务，而不是让用户忙着维护虚拟成就。

### 4.6 kaoyan_shuati：最应学习的是题库生产纪律

**观察（D/C）**：Android 政治刷题与解析流水线；README 公开列出了文档口径不一致、桌面构建路径等问题。test_kaoyan_feedback.py 针对选项混入章标题、解析串题、修正幂等性，以及种子库与 Android 资源同 ID 一致性做回归。[S6][C5]

**值得借鉴**：每次勘误成为可复跑修正，不只在运行库里手改一下。

**落地到我们**：题卡“报告问题”自动带 question_id、版本、字段、截图区域与来源。确认修正后生成补丁与回归样本，重建题包，发布修订说明。用户自己的笔记与作答不能随修订丢失。

**政治专项提醒**：标签不能长期停留在粗粒度五类映射。新增概念体系时应保留 source taxonomy、目标 syllabus_version 与人工映射记录；旧题按命题年份理解，不能让当前口径无声覆盖历史答案。考试分类调整须再核对当年权威大纲，本报告不把竞品分类当官方标准。

**边界**：仓库明确区分代码与商业出版物内容许可。借鉴质量流水线，不把题库文件存在于 GitHub 当成再分发许可。

### 4.7 考公刷题：主观题 AI 必须理解“材料”和“采分点”

**观察（D）**：区分行测解析、申论批改、识图转写、学习建议和导入解析等任务，提示词可管理；数据许可独立于代码。[S7]

**值得借鉴**：不同任务使用不同输入契约和提示词；批改包含材料与参考要点，而不是仅问模型“这题得几分”。

**落地到我们**：数学输入题干、学生步骤与标准步骤；政治输入材料、设问、命题年份和要点；408 输入算法/计算过程及边界条件。先保留人工评分权，再积累模型与人工分歧案例。

**边界**：申论套路不能原样迁移成政治评分，更不能用于数学证明。技能包需要逐项审查，不能自动执行外部包里的任意指令或脚本。

### 4.8 学之思 xzs：借鉴考试模型，不变成学校管理平台

**观察（D）**：Java + Vue 考试系统，包含学生与管理端、试卷和多题型相关模块；公开分支与商业产品入口应区分。[S10]

**值得借鉴**：模板定义结构、生成的试卷固定内容、答卷记录学生作答、阅卷结果单独保存。

**落地到我们**：补齐 exam_blueprint、paper_snapshot、attempt、grading 四层关系，重生成题库不改历史答卷。时间、总分、小问分值、题目顺序都写入快照。

**边界**：不迁移 Java 后端，不优先做班级、角色审批、排行榜和防作弊平台。AGPL 代码若直接复用需按实际组合与分发方式评估义务；本报告主要借鉴模型思想。

### 4.9 Anki / FSRS：让错题进入未来，而不是只留在过去

**观察（D/C）**：Anki 聚焦间隔重复；FSRS4Anki 提供调度与参数优化资料。Anki 的许可证是 AGPL-3.0-or-later 并有组件例外，不能因 API 显示 Other 就当作无许可；FSRS4Anki 为 MIT。[S8][S9][C6]

**值得借鉴**：今天到期的学习项是一等对象，每次复习产生新事件，历史可追溯。

**落地到我们**：review_item 不必等同于整道大题。可拆成“原理回忆”“关键计算步骤”“完整题迁移”三种练习，先为知识回忆与短步骤安排调度。随机刷题答对，不直接当成已经长期掌握。

**边界**：FSRS 的记忆预测不能被宣传为考研分数预测；重复看过答案的题会污染掌握判断。冷启动使用合理默认参数，样本不足不训练个人参数。具体 Python/TS 库与版本需要在实施阶段单独评估；不直接复制旧版 Anki 自定义调度脚本进我们的数据库。

### 4.10 Open Notebook：有引用的讲解，比“很像老师”更重要

**观察（D）**：支持资料上下文选择与引用。官方 citations.md 明确说明引用指向整份 source/note/insight，不携带页码、段落高亮；引用由模型选择，可能漏引或错引。[S11][C7]

**值得借鉴**：用户能控制交给 AI 的资料，并从回答跳回来源。

**落地到我们**：复用已有 source_regions / analysis_regions，为回答建立 question_id → document_id → page → bbox 或文本片段的引用链。不能定位时显示“整份资料引用”，不能伪造页码。

**边界**：引用存在不等于论证正确。先用小规模已审核资料检索，不立即引入一个独立大型知识库服务，更不为了 RAG 重写现有后端。

### 4.11 Super Productivity：桌宠背后应该有真实的任务状态

**观察（D/C）**：任务、时间规划与专注管理；提供多种同步/备份方案。electron/backup.ts 可见备份目录、IPC 入口与保留策略相关实现。[S12][C8]

**值得借鉴**：任务有上下文，专注计时与任务关联，备份与恢复是正式功能。

**落地到我们**：今天到期 8 道错题 → 生成一个 20 分钟任务 → 点桌宠打开固定待办栏 → 开始练习 → 完成后同步任务状态。提醒可暂停，考试模式安静。

**边界**：不把所有任务同步工具都搬过来。先修正 SQLite 学习记录与 localStorage 待办/草稿之间的数据保护边界，再考虑 WebDAV 或伴随端同步。

### 5.3 四个容易被“功能已做完”掩盖的问题

**一，有大题但在线练习拿不到。** practice.py 的 catalog_from_rows 跳过非 choice；main.py 的练习取题同样限制 choice；提交模型为 selected_options。需要改题型协议，而不仅是增加一个按钮。[L2]

**二，408默认模板不是严格的原卷还原。** presets.py 当前综合模拟卷为四科合计40道选择题，再加5道综合题，150分、180分钟；名称已标注“可调整”。参考408Lab历年卷采用40+7，但不能仅凭竞品定义考试标准。建议维持现有模板兼容性，新增经官方当年资料或可靠原卷核验的 blueprint_version，明确“练习模板”与“年度仿真模板”的差别。[L5][S1]

**三，Agent 的候选集也会影响出卷。** agent_composer.py 将每分区候选截取为 max(120, count×3) 个，再让模型返回ID。这个限制不是全局固定120上限；当候选排序不均衡时，截取可能造成覆盖偏差。应该先做分层候选采样、记录截取依据，再比较AI相对规则的增益。[L3]

**四，离线数据仍可能分散。** PracticeView 的草稿、PetTodoPanel 的待办读取 localStorage，练习记录还在 SQLite。只拷贝 sqlite 文件不能据此断言恢复了整个工作台。应定义一份完整用户数据清单。[L6]

## 7. 可以直接转成开发任务的设计

### 7.1 主观题：先把“我写了什么”保存下来

用户故事：选408综合题，分小问作答，离开后恢复，交卷后对照评分点自评，再决定是否请求AI建议。数学与政治使用同一作答底座，评分规则按学科扩展。

**最小完整流程**：

1. 题卡明确显示解答题/简答题、分值、小问与来源。
2. 支持文本/公式；手写图片先作为附件，不强制OCR。
3. 作答过程中隐藏标准解与提示，自动保存草稿。
4. 提交后按小问展开参考解与评分点，自评记录为 self_assessed。
5. AI建议单独存为 suggested，用户确认后才影响最终自评分。
6. 复盘选择“概念不清/步骤缺失/运算错误/时间不足”等，可自定义。

**数据建议**：QuestionPart、RubricPoint、AttemptAnswer、GradeRevision。评分点有最大分、得分依据、适用版本；多种正确解法可以对应不同评分路径。缺乏可信rubric时只能给定性反馈或自评分，不能自动创造“官方评分标准”。

**验收**：三学科各至少10道已核验样题，包含多小问、图片、另一种正确解法、空答；刷新/重启不丢；总分不超上限；查看答案后的重做与首次独立作答分开统计。

**改动入口**：[practice.py](../backend/app/practice.py)、[main.py](../backend/app/main.py)、[PracticeView.tsx](../frontend/src/components/PracticeView.tsx)、数据库迁移。

### 7.2 题库质量：把“导入成功”拆成三种状态

- 结构合格：ID、题型、选项、答案、图片引用与分值满足契约。
- 来源可追溯：repo/source文件、原始题号、版本、授权说明可查。
- 内容已核验：人工确认题干、答案和解析；审核人/日期有记录。

自动校验通过不能直接提升为内容已核验。题卡至少显示来源类别、年份、审核状态与“报告问题”。

**版本规则**：question_id 保持稳定，question_revision 单独递增；历史试卷绑定快照。纠错后提示旧记录使用过不同答案，不能静默改写过去得分。文本指纹只能辅助去重，同题不同问法或改编题保留关联关系，不强行合并。

**验收**：缺答案、解析串题、选项重复、缺图、政治年份不明各有检测案例；一条修正可以从反馈重放到最终题包；题包更新不会恢复用户删除题，也不会覆盖用户笔记。

### 7.3 复习调度：把“今日待办”接到真实学习任务

起步分三个队列：到期复习、首次错题短间隔回访、新知识练习。用户可限制每日时间，队列显示预计用时和选入原因，超量时允许顺延。

复习事件保存：题目/知识项ID、时间、是否独立作答、是否看提示、自评难度、结果、用时和调度版本。先有事件日志，再接算法。刷题答对和回忆卡评级的映射需要实测，不能无条件把正确=Good。

**验收**：固定时钟可重现到期结果；修改系统时区不重复生成任务；算法升级可回放；看答案后的作答不会被当作独立掌握；用户能暂停某类复习。

**与现有偏好一致**：使用当前工作台和桌宠待办栏展示，不恢复独立知识地图/学习记录仪。

### 7.4 试卷模板：模板是合同，不是几个数字

新增考试蓝图包含：学科、适用年份、题型/小问结构、分值、时长、科目约束、资料出处与验证状态。原卷模式严格保持题序；模拟模式按蓝图组题，并显示与目标分布的差异。

生成前显示库存诊断：“计算机组成原理综合题不足2道”要明确报出，不能偷偷用选择题补齐。生成后保存模板版本、题目版本、随机种子、规则/Agent模式及验证结果；历史卷可重现。

保持现有界面决定：默认只放408综合模板；顶部“增加408模板套件”按需添加专项，重复操作幂等。Agent仍默认关闭，开启时配置Key。

**验收**：题数、总分、科目分布、小问加总、去重全部通过；库存不足不能产生貌似完整的卷；用户修改的旧模板不被迁移覆盖。

### 7.5 AI：先提示，后答案；先证据，后自信

提供三级提示：识别考点 → 给出下一步 → 展开完整参考解。默认逐级请求，并标记本次练习已使用提示。AI批改显示“命中的评分点、遗漏点、所依据片段、置信状态”，允许人工改判。

请求前展示将发送的题干、学生答案和资料范围；沿用当前Key仅内存的默认策略。请求有取消、超时、预算提示和可理解错误；若以后允许记住Key，需用操作系统安全存储并提供删除。

**对Agent组卷的改进**：候选集按考点与难度分层，输出选题原因，硬约束仍由本地验证；失败时让用户明确选择重试或切规则，不悄悄换模式。

**安全与质量契约**：材料里的指令当资料处理；模型只能返回约定结构，不能执行代码或任意访问文件；不将私有作答写入诊断日志；评测覆盖提示注入、错误引用、超长材料、模型拒答和格式错误。

### 7.6 分发：轻量应用 + 可选题包

建议应用与内容更新解耦：安装包提供界面/运行时/小型入门包，完整数学、政治、408包按需下载；支持离线导入，不能要求每次启动联网。

题包manifest增加版本、schema、文件尺寸、校验值、来源、许可与最小客户端版本。下载写临时目录，校验成功后原子切换；中断可恢复，旧版本可回退。图片按内容寻址去重，避免同图多份。

不要贸然清理Git历史。先测量代码、图片、桌宠素材和题包的体积，再独立决定Release资产或对象存储；迁移说明必须覆盖已有用户。

**验收**：无Python/Node的干净Windows环境安装启动；断网仍可练已下载题；不完整题包拒绝启用；升级失败可恢复上一个可用版本。

## 8. 架构建议：在现有底盘上长，不推倒重来

保留 Electron + React + FastAPI + SQLite。建议按领域逐步抽出接口：

| 领域 | 职责 | 与现有代码关系 |
|---|---|---|
| Content | 题目、小问、来源、版本、题包 | 延伸现有questions与bundle加载器 |
| Assessment | 模板蓝图、试卷快照、校验 | 延伸composer/template_rules/presets |
| Practice | 会话、作答、草稿、评分修订 | 从main.py逐步抽路由与服务 |
| Review | 到期队列、事件、调度器 | 新增模块，消费作答事件 |
| Tutor | 提示、检索、引用、批改建议 | 在agent_composer之外分离职责 |
| Workspace | 待办、计时、备份、桌宠联动 | 保留现有组件，统一数据契约 |

新表/字段只是设计建议，不在调研任务中直接迁移生产数据。采取增量迁移、迁移前快照、失败回退。稳定ID和事件类型先定下来，再做同步。

**建议事件**：attempt_submitted、grade_confirmed、question_corrected、review_completed。记录schema_version与发生时间；可重放不意味着立即引入消息队列，单机SQLite事务和清晰服务边界足够起步。

**渲染**：Markdown/LaTeX、图片和交互图分别走受控渲染器；原始HTML净化；禁用任意脚本。题面不可通过素材URL绕过权限读本机文件。

**搜索**：先验证SQLite全文检索对中文、公式关键词和标签的效果，再决定是否需要额外搜索服务；不把向量数据库当默认必选项。

## 10. 如何衡量“变好了”

### 10.1 北极星与护栏

建议北极星：**每周完成复习，并在至少7天后独立做对关联题的有效学习项数**。同时区分原题复现与同考点新题迁移，避免只记住选项。它是拟议指标，本报告没有现成结果。

辅助指标：首次成功练习率、首次到练习耗时、主观题完整提交率、到期复习完成率、勘误解决时间、崩溃/白屏率、恢复成功率。总题量、在线时长、连续打卡不作为唯一成功指标。

### 10.2 建议首轮验收目标（非现状）

| 项目 | 建议目标 | 测量方法 |
|---|---|---|
| 首次使用 | 5名新用户至少4名在5分钟内完成首次练习 | 干净机任务观察；样本小，仅作早期信号 |
| 核心流程 | 20条E2E全部通过 | 导入、组卷、作答、恢复、导出、升级 |
| 数据恢复 | 定义的备份测试集100%通过 | SQLite+待办+草稿+附件校验恢复 |
| 题库结构 | 所有发布题满足schema、无缺失必需素材 | 自动校验；不等于答案100%正确 |
| 内容质量 | 先建立每科50道分层人工基准题 | 覆盖题型、年份、难度和含图题 |
| AI采分 | 相对两名审核者共识分，归一化MAE≤10% | 至少90份不同质量作答，报告分歧与置信区间 |
| AI误判 | 严重错误判满分案例必须归零后再扩测 | 独立负例集；达标仍非可靠性保证 |
| 引用 | 基准集可定位率≥95%，且单独审查支持性 | 检查引用位置与论断是否相符 |
| 性能 | 约8千题本地筛选P95≤300ms（暂定） | 固定普通Windows设备、预热/冷启动分开 |

性能阈值需在指定硬件测得基线后调整。AI成本按模型、输入输出token与单次会话记录，先给预算上限再扩大功能，不在没有实际调用数据时报每题成本。

### 10.3 必须覆盖的回归场景

- 后端未启动、端口占用、数据库迁移失败：显示恢复入口，不白屏。
- 题包缺图、断网、导出依赖缺失：定位错误，不生成空白“成功”文件。
- 作答后重启、时间变更、临界交卷：不丢记录、不重复扣时/提交。
- 模型超时、返回非法题ID、重复题、评分超限：硬校验挡住。
- 题目修订与旧答卷并存：旧快照仍能查看。
- 桌宠动画、多屏DPI、待办长列表：尺寸稳定，面板不挤压主体。

## 11. 三门学科需要不同的精细化

| 学科 | 重点训练单元 | 特别要防的错误 | 产品表达 |
|---|---|---|---|
| 数学一 | 计算过程、证明、方法选择 | 等价答案误判、公式OCR错误、漏步骤 | 原图对照、LaTeX、多解法、步骤自评 |
| 政治 | 概念辨析、材料对应、要点表述 | 历史口径混淆、机械关键词判分 | 年份/大纲版本、材料证据、要点与表述分离 |
| 408 | 算法、状态推演、系统计算 | 初始条件不同、过程跳步、改编未标 | 过程表、可视化、小问评分、边界条件 |

我们可以共享会话、保存、评分修订、标签与题源框架，但不应共享一套粗糙的“答案字符串相等”逻辑来处理所有学科。

## 12. 开源产品化与内容治理

1. **项目代码许可单独明确。** 本项目README仍提示未独立声明许可证；正式吸引贡献前应选定LICENSE，并梳理已纳入代码的兼容性。报告不代替维护者做许可决定。[L1]
2. **题源清单可机读。** 每个包记录来源、版本、代码许可、题面/素材许可、授权依据的内部索引与允许用途。公开索引不泄露合同或个人信息。
3. **功能借鉴与代码复用分开。** 学习界面流程不等于复制实现；实际移植组件必须保留适用声明。GPL/AGPL、MIT、Apache等差异应在具体复用方式确定后核对原文。
4. **贡献入口要小。** 提供“修一题”Issue模板：题ID、字段、建议修改、依据。自动验证PR里的schema与素材引用，人工确认答案。
5. **发布说明分两层。** 应用功能版本与题库修订版本分别发布；用户能知道今天修的是程序，还是题目答案。
6. **可选诊断而非默认上传。** 本地日志不记录Key与完整学生答案；若开展用户研究，单独获得参与者同意。

以上是工程与发布建议，具体许可义务以原始许可、内容授权与实际使用方式为准。已有授权应被落实为可维护记录，不被重复索要，也不被扩大解释。

## 13. 暂时不做什么

- 不恢复知识地图、学习记录仪大面板；保留相关数据供题内补弱使用。
- 不为追求功能列表加入多人社区、班级管理、题库交易和排行榜。
- 不一口气改写成Tauri/Next.js/微服务；当前架构足够支撑下一阶段。
- 不把AI生成题未经审核混入真题，不给没有证据的题标“官方答案”。
- 不把题量继续翻倍当作第一目标；先让现有主观题能完整作答。
- 不用更多弹窗补复杂流程；设置尽量渐进呈现，当前题目操作就近完成。

项目的个人风格值得保留：有桌宠、有一点俏皮话、有摊开书桌的感觉。考生卡在一道题上时，可以温柔；判断答案、保存数据和解释来源时，必须严谨。

## 14. 建议直接启动的第一个迭代

建议两周内的具体范围：

1. 定义主观题、小问、评分点与作答事件的数据契约。
2. 做统一备份/恢复的最小版本，并完成一次干净环境恢复。
3. 把现有408综合题中的10道人工核验样题接入“作答—自评—复盘”。
4. 给408模板加清楚的练习结构说明，规划年度蓝图版本，保留默认/专项套件交互。
5. 在题卡放上来源与问题反馈入口，把第一条勘误做成可复跑补丁。

如果资源不足，保留前3项，不压缩数据恢复与主观题保存验证。这个迭代完成后，用户才能明确感受到：之前只是看得到的大题，现在真的能练完。
