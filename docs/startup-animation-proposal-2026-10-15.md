# 窗口内首屏动画方案：书桌就位

日期：2026-10-15。按用户澄清修订：**仅处理 Electron 窗口已经出现，到首页显示具体内容之间的空白。** 当前为方案和交互样稿，尚未接入应用。

推荐视觉为“纸张装配 + 桌宠迎接”：沿用现有纸白底、黄色、青色、黑色硬边与实体阴影。三张科目纸卡归位，桌宠轻微活动；首页可显示后立即撤去动画。

- [交互样稿](prototypes/startup-animation.html)：在浏览器打开，支持 3 / 10 / 20 秒、加载失败、立即就绪、减少动态。
- [GitHub 数据与来源](research/startup-animation-github-2026-10-15.json)。
- 样稿的时间和阶段均为模拟，不连接后端、不修改学习数据。

## 1. 正确范围

```text
Electron 主窗口出现
  → HTML 首次可绘制时显示内联加载画面
  → JavaScript 模块加载 / 执行，React 挂载
  → 首页首屏内容可以显示
  → 动画撤去，露出同一个窗口中的首页
```

约 10 秒是用户观察值，尚未实测。上一版误将范围扩大到整个启动流程，所提后端启动编排、独立启动窗、打包体系调整及相应 2–4 天估算均撤回。

代码依据：[index.html](../frontend/index.html) 当前只有空 root；[main.tsx](../frontend/src/main.tsx) 静态导入 App 后挂载 React；[App.tsx](../frontend/src/App.tsx) 导入多个页面并在挂载后请求数据；[主窗口](../frontend/electron/main.ts) 创建后加载渲染器。

加载画面必须独立于业务包。仅把动画做成 App 内的组件，不能覆盖 App 模块尚未加载的时间。静态导入是待检查项，不是已证实的 10 秒瓶颈。

## 3. 视觉方案

| 方向 | 表现 | 判断 |
|---|---|---|
| A. 书桌就位，推荐 | 数学、政治、408 三张纸卡依次归位，桌宠迎接 | 与内容和现有界面一致，可随时收尾 |
| B. 纸张折叠标志 | 纸片组成叠纸标志，配简洁方块循环 | 作为简化或低动态版 |
| C. 桌宠短片 | 拿书、翻页、挥手 | 需要新增原创动作素材，首版投入更大 |

A 方案主标题为“书桌就位，今天继续。”入场约 1 秒，后续保持局部循环，默认静音。桌宠和图片加载失败时，纸卡与文字仍可显示。正式版可使用已选择角色，但不等待设置或图片才绘制。

首页可显示后用约 150–250ms 收尾，减少动态时直接撤去。启动快就早退出，不强制播放满 10 秒。等待超过约 12 秒仅提示“界面加载时间较长”，不把时间阈值当故障结论；实际模块加载失败则显示重新加载入口。

首版只需显示“正在载入界面”。有真实模块就绪与首屏事件后再切换文案，不显示“启动本地服务”，不伪造百分比。样稿的四段状态仅为演示。

## 4. 接入方式

1. **index.html**：模块脚本之前放内联 CSS 和独立加载层，位于 root 之外，不依赖 React、KaTeX、JSCPP。用极小前置脚本识别 surface，仅主窗口展示，桌宠、计时器、待办浮窗不被覆盖。
2. **main.tsx**：App 模块加载完成后通知加载层；开场素材不阻挡业务挂载。
3. **App 首屏**：首页提交且核心内容可显示后，经过绘制调度移除加载层。不能仅以 root 存在或 DOMContentLoaded 判定首页就绪。
4. **数据加载**：不把全部接口、招生资讯、图片与隐藏模块变成退出条件。已有首页内容先显示，尚未完成的数据用页面内加载状态；接口失败不永久遮挡首页。
5. **异常与清理**：入口模块或挂载失败提供重新加载；动画退出后清理 DOM、监听、计时器。Tab 切换、托盘恢复、桌宠唤醒不重播，全页重载才重新走首屏。

本次不改 start.bat、setup.bat、后端启动顺序或打包体系，不新建启动窗口。

### 首帧边界

内联画面也要等 HTML 到达并可绘制后才出现，不能承诺从系统窗口创建的第一个瞬间就有动画。实施时记录窗口 show、HTML 首次内容绘制、模块开始执行与 React 首屏提交。

若实测窗口出现到 HTML 首帧仍有明显空白，再小幅调整主窗口显示时机，让窗口在加载画面可绘制后显示；不是等整个首页完成才显示。开发服务若阻塞 HTML 到达，需要对这一段做同窗首帧处理。

若大段同步 JavaScript 导致阻塞，动画也可能卡顿。根据测量结果再考虑延迟导入尚未打开的页面，不在未定位前重构全部模块。

### 资源预算

原生 CSS + 少量 JS，无需安装新动画库。已有女仆 PNG 为 59,920 字节，动态 WebP 约 2.3MB，首版用 PNG 配轻微位移。动画以 transform / opacity 为主；当前应用禁用硬件加速，实际流畅度需验证。

采用 new-brutalist-ai-ui 的硬边框、实体阴影与平面色块原则。短入场与局部循环服务于用户明确提出的开场动画需求。

## 5. 验收

- 延迟业务模块时，内联画面先显示，无白屏等 React 的情况。
- 3 / 10 / 20 秒等待均能展示，首页先完成则先退出。
- 模块和挂载错误可重试，数据接口失败不永久遮挡已有首页。
- 远程资讯和图片不是退出条件。
- 桌宠、计时器、待办浮窗与托盘恢复不受影响。
- 减少动态有效，交接不闪白，监听与计时器正确清理。
- 分别测量“窗口到加载画面”和“窗口到首页内容”，不以样稿代替真实性能结果。

## 6. 验证记录

独立样稿已验证桌面、约 390px 窄屏、快速退出、加载失败重试、长等待与减少动态。现已接入 Electron 主窗口：启动层由 `index.html` 内联，业务入口通过 `main.ts` 延迟加载，辅助窗口按 `surface` 跳过启动层；`npm run smoke:boot` 已验证延迟模块首帧、最小窗口无横向溢出、首屏退出、错误重试和辅助窗口隔离。当前仍未建立真实机器上的窗口到首屏性能基线，smoke 只验证行为和交接。
